Crestron programming, as learned so far

A Crestron system is a control processor plus touch panels. The processor runs a compiled program. The panel is either a native Crestron touchscreen or a web page that speaks the same control protocol. This note covers the three languages used in this catalog — SIMPL+, Simpl#, and CH5 — in semi-technical language, with enough concrete rules that another person or AI can start work without rediscovering the landmines.

Last updated 27 August 2026. Public repo: Prophet6/Crestron-HTML5. Companion modules: Prophet6/Crestron-Modules. Not affiliated with Crestron Electronics.

The big picture

Think of a Crestron job as three jobs that meet in the middle. Someone has to decide what happens when a button is pressed (room logic). Someone has to talk to hard devices (displays, DSPs, matrix switchers) over TCP or serial. Someone has to draw the buttons a person actually touches. Those three jobs are SIMPL+ / SIMPL Windows, Simpl#, and CH5.

CH5The touch UI. A web app packaged as .ch5z. It does not run the building; it only sends and receives signals.
CIP / IP-IDThe phone line. Each panel has an address (IP-ID) on the processor. Digital, analog, and serial signals travel this path.
SIMPL WindowsThe patchbay. You drag symbols onto a sheet and draw wires between pins. This is the program that loads onto the processor as .lpz.
SIMPL+Custom symbols on that sheet. Event-driven modules with named pins. Good for room logic, interlocks, feedback.
Simpl#A C# library the SIMPL+ module can call. Use it for sockets, parsing, threading — work SIMPL+ is awkward at.

Mental model: the panel is a remote control. The processor is the brain. SIMPL Windows is how you plug the remote into the brain. SIMPL+ is a custom brain module. Simpl# is a library that module can load. CH5 is how you draw a modern remote without Crestron’s visual UI builder (Construct).

You almost always ship two things: a processor program and a panel package. Changing the UI does not change the program unless the signal names or join numbers changed. Changing SIMPL+ pin order does break existing wires on the sheet — treat pin order as a public API.

Signals — the common language

Every layer speaks three kinds of signal. Learn these first; everything else is routing them.

KindWhat it isTypical useRange / notes
DigitalOn or offButton press, mute, “wall is open”A pulse is a short high. A held signal stays high. Feedback (FB) is usually held.
AnalogA numberVolume, source index, countdownCrestron analog is 0–65535. Percent UIs map 0–100 ↔ that range.
SerialTextRoom name, countdown stringSIMPL+ native strings use a $ suffix (Status$).

Direction matters. A press travels panel → program. Feedback travels program → panel. In CH5 contracts the names are “events” (panel pressed something) and “states” (program is telling the panel the current value). In the CHD extender file those labels are easy to get backwards — see Contracts.

SIMPL Windows — the patchbay

SIMPL Windows is Crestron’s graphical programming environment. You do not write a main() for the whole job. You drop symbols (factory modules and your own SIMPL+ symbols) onto a sheet and connect pins with wires. The compiled result is a program the processor runs.

  • Tool: SIMPL Windows (Crestron installer). File type .smw.
  • Compile: F12 / Build. Output is .lpz (plus .sig / .sm2 sidecars).
  • Load: Crestron Toolbox → the processor. The lab program for Divisible-Room lives in Divisible-Room/simpl/.
  • Do not commit: .ASV autosaves, SPlsWork/ generated glue, *_compiled.zip.

HTML5 XPanels are symbols on this sheet too. Each one has an IP-ID (this lab: room panels E1/E2/E3, master C1). After you attach a .chd contract, that XPanel grows named extender pins instead of (or in addition to) numbered joins.

Fan vs one-instance. Feedback that every panel must show (wall open/closed) is fanned: one Logic output wire split to every XPanel. Identity and Power Shutdown Confirmation are one instance per panel — do not fan a single Identity to E1, E2, and E3.

SIMPL+

SIMPL+ is Crestron’s module language. It looks a bit like a simplified C. A .usp file declares pins, then reacts when those pins change. After compile, SIMPL Windows shows it as a rectangle with rows of inputs on the left and outputs on the right.

Use SIMPL+ for: room combination rules, last-wins overrides, mapping source buttons to analog values, identity (“this panel is Room B”), and wrapping a Simpl# library so the sheet can talk to it.

The symbol is a three-column grid

This is the most important Crestron-ism in the whole note. The symbol is not two independent lists. It is a spreadsheet: 

Input  |  Parameter  |  Output

Related signals share a row so a human can see A_Laptop across from A_Laptop_FB. Empty cells are filled with _SKIP_. That skip is not dead code. It pads the list so the next real pin lands on the intended row.

  • Declare digital in/out before analog or serial.
  • If digital input count ≠ digital output count, analog pairs drift to the wrong rows. Pad the shorter digital list with _SKIP_ until the counts match.
  • Group similar signals. Put a skip between dissimilar groups (analog source FB vs serial room names).
  • Trailing _SKIP_ with nothing after it does not create a pin. Skips only matter before a real signal.
  • Do not restack I/O to look neat unless the user asked, or you are restoring this alignment. Pin order is the public API of the symbol.

Canonical example — Divisible Room Logic wall block (user order; do not restack):

DIGITAL_INPUT  Wall_AB_Sense, Wall_BC_Sense,
               _SKIP_,
               Wall_Combine_All, Wall_Divide_All,
               Wall_AB_Toggle, Wall_BC_Toggle,
               _SKIP_,
               A_Power, A_Mute, …          /* then B, C, then vol ± */

DIGITAL_OUTPUT Wall_AB_Open_FB, Wall_BC_Open_FB,
               _SKIP_,
               _SKIP_, _SKIP_, _SKIP_, _SKIP_,   /* no FB for combine/divide/toggles */
               _SKIP_,
               A_Power_FB, A_Mute_FB, …

Parameters

Parameters are compile-time settings on the symbol (dropdowns, numbers). They have no CHANGE event. If you need a runtime override, add an analog input and treat parameter as the default.

Never #DEFAULT_ARG. On SPlus 4.06 / SPlusCC it is Error 1100 (statement outside function). Use #BEGIN_PARAMETER_PROPERTIES with propDefaultValue = 0d and a propList for dropdowns. Integer literals in that block take a d suffix. Canonical: Divisible Room Identity.usp. 

INTEGER_PARAMETER Panel_Role;

#BEGIN_PARAMETER_PROPERTIES Panel_Role
    propValidUnits =        unitDecimal;
    propDefaultUnit =       unitDecimal;
    propDefaultValue =      0d;
    propList =              {0d, "Master Panel"},
                            {1d, "Room A"},
                            {2d, "Room B"},
                            {3d, "Room C"};
    propShortDescription =  "Select which room this panel should control";
#END_PARAMETER_PROPERTIES

Types, comments, and events

TopicRule
Native stringsSTRING x$[64]; and Status$. The $ is only for native SIMPL+ strings.
Simpl# stringsSimplSharpString msg — no $.
No ushortC# ushort in a callback is SIMPL+ INTEGER.
No C-style notIf (value = 0), never If (!value).
Comments in logicInside Function / CHANGE / PUSH / CALLBACK bodies: /* */ only. // there is Error 1100. Headers and parameter-property blocks may use //.
Line endingsCRLF required on every .usp. LF-only is Error 1700 (EOF at line 1). Normalize after every AI edit.

Typical event handlers:

  • PUSH pin — rising edge (a press).
  • RELEASE pin — falling edge.
  • CHANGE pin — analog or serial changed.
  • FUNCTION Main() — startup. End with WaitForInitializationComplete() when talking to Simpl#.

How SIMPL+ gets compiled

The compiler is C:\Program Files (x86)\Crestron\Simpl\SPlusCC.exe. Do not stop at “0 errors in the SIMPL Windows editor.” Linking still has to generate glue under SPlsWork\. 

& "C:\Program Files (x86)\Crestron\Simpl\SPlusCC.exe" `
    \rebuild "C:\full\path\Divisible Room Logic v1.0.usp" `
    \target series4
StepWhat it means
SIMPL+ compileSyntax check of the .usp. Zero errors ≠ done.
Library compileLinks any Simpl# .clz for the requested series.
Cross-compile / linkWrites SPlsWork\*.cs and *.dll. Read this if the link fails.
Symbol updateRefreshes the .ush that SIMPL Windows shows on the sheet.

Target: this lab is 4-Series, so \target series4. A Simpl# library built with the modern NuGet SDK is 4-Series only. A VS2008 / Windows CE library can be series3 series4. Compile one .usp at a time if a batch drop the glue DLL.

Success looks like: .ush next to the .usp, plus SPlsWork\<Module>.dll. Then compile the .smw and load the .lpz.

Simpl#

Simpl# is C# that runs on the processor, in a sandbox closer to .NET Compact Framework than to modern .NET. Use it when SIMPL+ would become a pile of string parsing and socket retries — device protocols, Telnet, shared connection state used by several modules.

Typical split: one Simpl# core owns the TCP connection and raises callbacks. Several SIMPL+ satellites subscribe to that same core (router, serial, UI feedback) instead of each opening their own socket.

  • APIs: Crestron.SimplSharp, Crestron.SimplSharp.CrestronSockets (TCPClient, CTimer, CMutex, SimplSharpString, ErrorLog).
  • Avoid: LINQ, async/await, HttpClient, full .NET HTTP stacks.
  • Line endings: .cs must be CRLF. LF-only files fail the Crestron C# toolchain even when the code is correct. UTF-8 with BOM is safe.

How SIMPL+ calls Simpl#

#USER_SIMPLSHARP_LIBRARY "Arranger_v1"
ArrangerCore Core;

That declaration makes the cross-compiler emit CORE = new …ArrangerCore(); in generated glue. Therefore the C# class must have a public parameterless constructor, even if you intend a singleton.

Singleton rule. The first public constructor must set _instance = this. The module that owns Connect/Disconnect lets auto-new run. Satellite modules rebind in Main(): Core = ArrangerCore.Instance; before RegisterDelegate. If you skip this, each module gets its own TCP client and they never see each other’s traffic.

MechanismSIMPL+ callC# side
EventsRegisterEvent(obj, EventName, HANDLER)event EventHandler<…>
DelegatesRegisterDelegate(obj, PropertyName, CALLBACK)A delegate exposed as a property
  • RegisterDelegate 2nd argument is the property name (OnLineReceived), not the delegate type name.
  • 3rd argument must be a CALLBACK FUNCTION, not an ordinary Function.
  • Do not use += on Simpl# delegates from SIMPL+.
  • If several modules register on one instance, Simpl# must append handlers, not replace them.

TCP receive loops: always re-arm ReceiveDataAsync while connected, including when bytesReceived <= 0. Never empty catch { } — log with ErrorLog.Error.

Rebuild the .clz first, put it next to the .usp (or in the user SIMPL+ folder), then SPlusCC \rebuild every dependent module. A net48 CLZ targeted at 3-Series reports “The archive does not contain a valid SIMPL# assembly.”

If SIMPL+ shows 0 errors but the link fails, open SPlsWork\<module>.cs and look at LogosSimplSharpInitialize() — that is the real error.

CH5 / HTML5

CH5 is Crestron’s name for HTML5 user interfaces. Construct is Crestron’s visual builder that emits CH5. This catalog does not use Construct. A .ch5z is just a zip of a web app. We write that web app by hand: vanilla TypeScript, Vite, CrComLib.

CrComLib is the JavaScript library that publishes and subscribes signals. On a TST-1080 the panel’s native stack carries CIP. In Chrome, WebXPanel opens a WebSocket to the processor and pretends to be a panel. Same UI package, two transports.

Talking to the processor from JavaScript

CrComLib types: b digital, n analog, s serial, o object. Names are always strings.

pulse(Joins.wallABToggle);                 // digital press
publishAnalog(RoomJoins.A.volume, 32768);  // analog
subscribeDigital(Joins.wallAB, (v) => { … });

In this catalog, UI code never hardcodes "21". Named maps live in src/crestron/joins.ts. Hello-World still uses numbered joins. Divisible-Room uses name-based contracts (Walls.ABOpen, RoomA.Laptop).

getBooleanSignalValue defaults to false when it has never heard a 1. Do not poll wall FB at startup with that API — a default false will paint “closed” over a live open wall. Subscribe, and wrap incoming native booleans (bridgeReceiveBooleanFromNative) so the UI sees every transition. Localhost without a processor will not show processor-owned overlays (power confirm); the UI may run a local fallback timer.

Contracts versus numbered joins

Numbered joins are “digital 21 on this XPanel.” Contracts are a named dictionary both sides share. Three files are generated together (Divisible-Room/scripts/generate-contract.mjs):

FileUsed by
contracts/divisible-room.cse2jCH5 archive (ch5-cli archive -c) and WebXPanel mapping
public/config/contract.cse2jRuntime copy at the path CrComLib expects
contracts/divisible-room.chdSIMPL Windows: Project → Manage GUI Extenders → Commit

CHD Input = program → panel (states). CHD Output = panel → program (events). After commit, set Control Join Ids: 1 Walls, 2 Identity, 3 PowerConfirm, 4 RoomA, 5 RoomB, 6 RoomC. Do not also wire numbered joins for the same signals.

Changing the contract (new enable pins, renamed signals) requires: regenerate → rebuild .ch5z → re-commit the CHD in SIMPL Windows → compile and reload the processor program → deploy the new UI. Forgetting the CHD re-commit is the usual reason a new signal exists in CH5 but never shows up in Debugger.

How a programmer actually uses this

  1. Decide the signals. Button presses, feedback, analogs. Write them down as names, not join numbers, if you can use a contract.
  2. Write or extend SIMPL+. Add pins in the correct group with matching _SKIP_ on the other column so existing rows do not shift. CRLF. SPlusCC \rebuild.
  3. Reach for Simpl# only when the module would otherwise grow a protocol stack. Rebuild the .clz, then every dependent .usp.
  4. Wire the sheet. Fan global FB. One Identity and one Power Confirm per XPanel. Drive enable lines from SIMPL, not from the UI guessing interlocks.
  5. Generate the contract so CH5 names and CHD pins match. Commit the CHD on each XPanel.
  6. Build the UI against those names. Optimistic local state is fine for a press; never let a default-false read stomp real FB.
  7. Ship two artifacts: .lpz to the processor, .ch5z to the processor (web) and/or TST-1080.
  8. Prove it in Debugger on the processor, then on the glass. A signal that moves in Debugger but not on the UI is a contract/name/subscribe bug. A UI press that never hits Debugger is publish/IP-ID/wiring.

Interlocks that are about the building (do not orphan rooms, do not close wall AB while BC is still combined) belong in SIMPL, exposed as enable inputs. The HTML5 panel should show or disable buttons from those enables, not invent a second copy of the rule.

Start here — instructions for another AI

Read this page, then Divisible-Room/docs/CONTRACT-MAP.md, Divisible-Room/docs/simpl.md, and ~/.grok/skills/crestron-simpl/references/crestron-programming-nuances.md before editing .usp / .cs.

  1. Identify the layer: sheet wiring (.smw), SIMPL+ (.usp), Simpl# (.cs), or CH5 (src/).
  2. After any .cs or .usp edit, normalize CRLF before compile.
  3. Before any SIMPL+ I/O edit, draw the Input | Parameter | Output grid. Add matching skips. Do not restack existing pins unless the user asked.
  4. Compile Simpl# .clz first, then each dependent .usp with SPlusCC.exe. Zero SIMPL+ errors is not done until SPlsWork glue exists.
  5. Never modify _archive unless asked.
  6. CH5: named contracts for Divisible-Room; numbered joins only for Hello-World. Quote paths with spaces. Archive to archive/.
  7. If volume lives in the right rail, listen on .workspace (or a parent that contains the rail), not only #zones. Put data-room on the moved volume card.
  8. Do not poll digital FB with a default-false reader. Subscribe and handle incoming native booleans.
  9. Do not put secrets in git. Deploy via env vars.
  10. When UI and Debugger disagree, state which direction failed (press never left the panel, or FB never arrived) before changing both sides.
